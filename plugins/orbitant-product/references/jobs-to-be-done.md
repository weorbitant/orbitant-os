# Jobs To Be Done (JTBD)

**Origin.** Clayton Christensen (Harvard, the *"job to be done"* theory, the *milkshake*
example) and Tony Ulwick (*Outcome-Driven Innovation*, *Jobs to Be Done: Theory to
Practice*).

## Core idea

People don't "buy products": they **hire** a solution to make progress in a specific
circumstance. The unit of analysis isn't the user or the product, but the **job** they're
trying to get done and the **outcome** they're pursuing.

This shifts the focus from "what feature do they want" to "what progress are they trying to
make, and in what context" — more stable and less biased toward a preconceived solution.

## How it's applied in the guide

- Block **1 (current situation)**: "how do they solve it today?" reveals the solution the
  user already *hires* (even if it's a manual process or a spreadsheet).
- Block **2 (problem)**: state the pain in terms of the progress sought, not the desired
  feature.

## Source

- Clayton Christensen et al., *Competing Against Luck*.
- Tony Ulwick, *Jobs to Be Done: Theory to Practice*.
